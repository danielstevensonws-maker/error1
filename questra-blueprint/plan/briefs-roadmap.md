## To write, in build order

**03 — Character Sheet Computation.** From wizard choices + rules data → the full derived sheet (HP, AC variants, saves, skills, slots, attack cards with riders, passive scores), every value carrying its derivation object for info-layer 2. Worked example: a complete Fighter 1 and a caster (SRD Wizard 3, to exercise slots/DCs). Non-goals: wizard UI, level-up flow (07). *Needed by: the slice's fixture PC, the player hub, encounter math.*

**04 — Conditions, Durations & Dying (Engine half).** The 15 conditions' full hook data (extends 01's Prone across all fifteen), the duration/expiry state machine (save-ends re-prompts, while-concentrating links), the dying state machine (death saves, stable, knock-out, memorial). Worked example: Hold Person end-to-end (Paralyzed application → auto-crit → save-ends → expiry). Non-goals: the dying-state UI (10).

**05 — Sync Channel & Permission Filter.** Wire protocol (join, snapshot+replay, sequence gaps, reconnect, presence), the per-viewer visibility filter as one function with a wire-level test harness, intent idempotency, the three viewer roles incl. table-display mode. Worked example: a captured session transcript from the Brief 02 trace, shown twice — DM wire vs player wire. Non-goals: any game logic (02 owns it).

**06 — Map Canvas, Tokens & Movement.** Grid model, the three-layer room (terrain/asset/trigger), asset metadata flags, token drag with live path cost + difficult terrain, edit/play/table modes of one renderer, DM-revealed fog geometry, AoE template shapes + affected-token query, staged tokens. Worked example: the vertical-slice room, fully serialized. Non-goals: image *generation* (09), computed line-of-sight (v2, per ADR).

**07 — Rests, Leveling & Downtime.** Rest transactions (incl. interruption ladder), the level-up flow as wizard-step components consuming class level tables, milestone/XP modes, the shop card + coin transactions. Worked example: Fighter 4→5 (ASI choice + Extra Attack + Second Wind 3 uses). Non-goals: multiclass (ADR: v2).

**08 — Boss Machinery & Prompts.** The one prompt-the-holder interrupt component and its four consumers (OA, legendary, lair, readied actions), legendary resistance interrupts, reaction economy edge cases. Worked example: a legendary boss round from the SRD dragon data. Depends on: 02, 04.

**09 — AI Touchpoint Pack (three briefs, one per tier).**
- **09a Image:** the prompt-assembler function (Portrait spec's four layers as code), NPC/asset token tables, library write path, quotas. Worked example: the Portrait spec §5 prompt, generated by the function byte-for-byte.
- **09b Creative text:** context recipes + the campaign digest job + each JSON schema with a worked accept/tweak/reject round-trip.
- **09c Table-time:** the latency stack (cache prefix layout, pre-warm triggers, timeout→fallback ladder, the difficulty-ladder fallback table), `RulingSuggestion` and `NpcLine` end-to-end. Non-goals across all three: model choice by name (config, not code).

**10 — Player Hub & DM Screen (UI briefs).** Component trees mapped to primitives, the first-contact states (onboarding hooks), the dying-state hub flip, contextual greying wired to the shared legality function. Worked example: hotbar rendering of the Fighter fixture incl. a rider card. Depends on: 03, 05.

**11 — Campaign & Session Data Ops.** CRUD surfaces, pull-from-campaign reference semantics, promotion re-parenting (both directions) as transactions, bonds-web data ops, recap/digest background jobs, campaign export format (doubles as fixture format). Non-goals: play events (02), AI drafting (09b).

**12 — Community Library & Moderation.** Publish pipeline, versioning/lineage, DM-approval allowlist enforcement points, report/review queue, balance-check computation as data (tier-breakpoint DPR math). Depends on: 01 (homebrew conforms to schema).

**13 — Onboarding Gating.** The floor-state machine on the account, existence-gating flags each surface reads, the silent campaign scaffolding writes, the demo party fixture, veteran skip. Written last, like the feature.

## Gaps this roadmap itself surfaced (new, small, worth capturing now)
- **The demo party** (Onboarding Floor 3) is a *content* deliverable — pre-built characters + a tuned first fight. Owns a home in 13 but someone must author it; it's the first thing a new DM ever plays, so it deserves design care, not fixture leftovers.
- **Narration template pack** — Brief 02's step 8 needs a writing pass (the Engine's plain-English voice is product voice; templates per outcome × tone). Small, but it's the sentence users read most often in the whole app.
- **The difficulty ladder table** (09c's fallback) is rules *content*: typical DCs 10/13/15/18/20 with plain-language labels — five rows, but it must exist as data.
- **Telemetry taxonomy** — accept/tweak/reject logging (AI spec §4) plus slice latency metrics need one small analytics event schema in contracts before anything can be measured.
